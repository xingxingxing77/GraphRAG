## 3. Zustand Store 设计

```ts
// stores/authStore.ts —— token 不落 localStorage 明文可选项: 视安全要求选 sessionStorage
interface AuthState {
  token: string | null; user: { id: string; name: string; role: "user"|"admin" } | null;
  login(grant: LoginGrant): Promise<void>; logout(): void; relogin(): Promise<boolean>;
}

// stores/chatStore.ts —— 单会话视图态
interface ChatState {
  messages: ChatMessage[];                 // user | assistant(AssistantMessage)
  streaming: boolean;
  thoughtSteps: ThoughtStep[];             // 由 updates 事件聚合(03 §3.5)
  typewriterTarget: string | null;         // 终态 answer, TypewriterText 消费后置空
  degradedReasons: string[];               // values.degraded_reasons ∪ X-Degraded 头
  activeTier: Exclude<LatencyTier,"auto">; // 用户选择, 默认 standard
}
```

- `configStore`：启动时拉 `GET /config/public` 缓存 models/tiers/compression 枚举（02 §3.7）
- `sessionStore`：会话分页列表 + 游标 + **时间分组视图**（按 `updated_at` 前端派生为 今天/7天内/更早 三组，v1.3 起无独立 `/sessions` 路由，由 ChatPage 左侧 `WorkspaceSidebar` 承载）；**线程惰性创建**——仅当该会话首条消息 `precheck` **miss** 且无 `thread_id` 时才 `client.threads.create()`（与 03 §8 对齐），不占 Postgres checkpoint；`session_id ↔ thread_id` 映射：有 thread 时 `thread_id` 即会话在 Agent 面的标识，无 thread 时 session 仅本地占位（precheck 命中亦不建 thread）。

## 4. axios 实例与拦截器

```ts
// api/http.ts
export const http = axios.create({ baseURL: import.meta.env.VITE_API_BASE, timeout: 10_000 });

http.interceptors.request.use(cfg => {
  const t = useAuthStore.getState().token;
  if (t) cfg.headers.Authorization = `Bearer ${t}`;
  return cfg;
});

let relogining = false;
http.interceptors.response.use(
  res => {
    const deg = res.headers["x-degraded"];                 // 03 §5
    if (deg) useChatStore.getState().pushDegraded(deg.split(","));
    return res;
  },
  async err => {
    if (err.response?.status === 401 && !relogining) {
      relogining = true;
      const ok = await useAuthStore.getState().relogin();  // 静默重兑换, 仅1次(03 §2.2)
      relogining = false;
      if (ok) return http(err.config);
      useAuthStore.getState().logout();
      location.href = "/login";
    }
    return Promise.reject(err);
  },
);
```

错误体统一为 `{code,message,detail}`（02 §2.3）——业务层用 `err.response.data.code` 匹配文案表（§9）。

## 5. Agent 面 SDK 封装（全站唯一入口）

```ts
// lib/agentClient.ts
import { Client } from "@langchain/langgraph-sdk";
const client = new Client({ apiUrl: import.meta.env.VITE_AGENT_BASE });

export function bindJwt(token: string) { /* SDK 默认取 localStorage 的 key, 或自定义 headers */ }

export async function ensureThread(sessionId?: string): Promise<string> {
  if (sessionId) return sessionId;
  const th = await client.threads.create();            // POST /threads (02 §4)
  return th.thread_id;
}

export function streamRun(threadId: string, input: ChatRunInput, cfg: RunConfigurable) {
  return client.runs.stream(threadId, import.meta.env.VITE_AGENT_ASSISTANT, {
    input,
    config: { configurable: cfg },
    streamMode: ["updates", "messages-tuple"],         // fast 档由后端自动追加 messages
    multitaskStrategy: "interrupt",                    // 同 thread 新 run 打断旧 run(03 §7)
  });
}
```

## 6. 核心 Hook：useChatStream（precheck → stream → 打字机 全编排）

```ts
export async function sendMessage(query: string) {
  const chat = useChatStore.getState();
  chat.appendUserMessage(query);
  chat.setStreaming(true);

  // ① L1 语义缓存短路(J22): 命中则不发起 run
  try {
    const pre = await precheck({ query, session_id });
    if (pre.hit) {
      chat.appendAssistant({ content: pre.answer!, citations: pre.citations ?? [],
                             degraded: false, cache_hit: true });
      return finish();
    }
  } catch { /* precheck 异常按 miss 处理, 不阻塞(03 §8) */ }

  // ② 发起流式 run
  const threadId = await ensureThread(sessionId);
  const stream = streamRun(threadId,
    { original_query: query, session_id: sessionId, user_id: user.id },
    { latency_tier: chat.activeTier, model: selectedModel ?? null });   // J2 覆盖默认条目

  for await (const ev of stream) {
    switch (ev.event) {
      case "updates": {                                   // 03 §3.3: thought 步骤来源
        const [node, delta] = Object.entries(ev.data)[0];
        chat.pushThoughtStep(node, summarize(node, delta)); // summarize 须穷举 AgentNodeName(02 §7); reflector:null → 显示"反思被短路跳过"
        if (node === "generator" && delta?.regenerated) chat.noteRegeneration();
        break;
      }
      case "values": {                                    // 终态(M1: 此前不得渲染任何中间文本为答案)
        chat.setFinalAnswer(ev.data.answer, ev.data.citations,
                            ev.data.degraded_reasons ?? []);
        break;
      }
      case "error": { showError(mapErrorText(ev.data.error.code)); break; }
    }
  }
  finish();
}
```

### 打字机渲染（M1/J20）

```ts
// hooks/useTypewriter.ts —— rAF 分片逐字; fast 档不走本 Hook(逐 token 直渲)
function useTypewriter(target: string | null, cps = 48) {
  const [shown, setShown] = useState("");
  useEffect(() => {
    if (!target) return;
    let i = 0, last = performance.now(), raf = 0;
    const step = (now: number) => {
      i = Math.min(target.length, i + Math.floor(((now - last) / 1000) * cps));
      setShown(target.slice(0, i)); last = now;
      if (i < target.length) raf = requestAnimationFrame(step);
    };
    raf = requestAnimationFrame(step);
    return () => cancelAnimationFrame(raf);              // 组件卸载即完成全文, 防截断
  }, [target]);
  return { shown, done: !!target && shown.length === target.length, skip: () => setShown(target!) };
}
```

- 读超时兜底：`AbortSignal.timeout(tier === "deep" ? 55_000 : tier === "standard" ? 30_000 : 10_000)`（03 §7）
  - `CHAT_504_TIER_TIMEOUT`：展示已收到的 thought 折叠区 + 重试按钮（重试同档；连败两次建议升 deep）

### 6.1 三档渲染状态机（统一 fast / standard / deep）

为避免 `06 §6` 中 fast（逐 token 直渲）与 standard/deep（终态打字机回放）两套渲染路径分叉导致气泡状态不一致，所有聊天消息渲染收口到以下有限状态机：

```
Empty（空态: "hi GraphRAG" 文案 + 建议卡 + 居中大输入框；messages 为空时展示）
   │ 提交查询（提交后切会话态: 输入框停靠底部, 消息流接管主区）
   ▼
Prechecking
   ├─ precheck.hit ─────────────► CacheHit       （直接渲染缓存答案, cache_hit=true；不建 thread）
   └─ precheck.miss ────────────► Streaming
                                        │  updates 事件实时累积 → ThoughtPanel
                                        │  （fast 档无 thought 折叠区）
                                        ▼
                    ┌───────────────────┴───────────────────┐
              fast: TokenStreaming                  standard/deep: AnswerReplay
              (messages 事件逐 token 直渲,             (values 到达后 TypewriterText 回放,
               不走 useTypewriter)                      fast 之外的唯一答案渲染路径)
                                        │
                                        ▼
              Done ── degraded? ──► DegradedBanner 常驻 + 气泡角标(degraded)
                  │
                  ├─ error 事件 / 流前 4xx·5xx ──► Error（按 06 §9 文案）
                  └─ 读超时(10/30/55s) ──────────► Timeout（展示已收 thought + 重试/升 deep）
```

约束（与 03 §4 M1 铁律一致）：standard/deep 在 `values` 到达前，气泡答案区**不得**渲染任何中间 LLM 文本，中间产物只进 ThoughtPanel。deep 档若 `updates.generator.regenerated` 再次出现，渲染 `RegenerationNotice`（"正在复核答案"）。`summarize()`（06 §6）须对 `AgentNodeName`（02 §7）全部成员穷举，新增图节点必须同步本状态机与 03 §3.4 样例。

## 9. 错误码 → UX 文案映射（与 02 §6 同步维护）

| code 前缀/具体码 | 文案 | 附加动作 |
|------------------|------|----------|
| AUTH_401_TOKEN_EXPIRED | （静默处理） | 自动重兑换 |
| AUTH_403_FORBIDDEN | 您没有执行此操作的权限 | — |
| CHAT_400_INVALID_TIER / EMPTY_QUERY | 输入有误：{message} | 输入框标红 |
| CHAT_429_RATE_LIMITED | 请求太频繁，请稍后再试 | 按 Retry-After 倒计时禁用按钮 |
| CHAT_504_TIER_TIMEOUT | 回答超时，可重试或切换深度模式 | 重试/升级 deep 按钮 |
| SESSION_404_NOT_FOUND | 会话不存在 | 刷新列表 |
| GRAPH_404_ENTITY_NOT_FOUND | 未收录该实体，试试其他关键词 | — |
| GRAPH_503_STORE_UNAVAILABLE + `no-graph` | 图谱服务暂不可用，已降级 | DegradedBanner 常驻 |
| SYS_500_INTERNAL / 503 | 服务开小差了 | 反馈入口 |
| SYS_400_VALIDATION | 输入有误：{message} | 对应表单标红 |
| SYS_404_NOT_FOUND | 页面或资源不存在 | 检查路径或刷新 |

`X-Degraded` → Banner 文案（**必须与 02 §2.4 逐值对齐**：02 增删取值须同 PR 更新本表，并补单测断言全覆盖）：`no-graph`="图谱检索不可用，已降级为向量检索"；`no-rerank`="精排暂不可用"；`llm-fallback`="已切换备用模型回答"；`budget-exhausted`="复杂度超预算，答案可能不完整"；`no-memory`="多轮上下文暂不可用"；`no-cache`="缓存层不可用，已按未命中处理"；`no-persistence`="对话未保存（存储暂不可用）"。

## 10. 设计系统：Beautiful UI

> 决策依据：架构文档 **J24**。完整落地计划（批次/令牌全量/图标映射表/风险）见 `前端设计系统落地方案.md`。

### 10.1 概述与策略

- 采用 **Beautiful UI**（beautifului.dev，MIT）作为统一设计系统层；组件源码由浏览器复制（**非 npm 包**），落 `src/components/bui/`。
- shadcn/ui 保留为基础原子层；BUI 组件是"设计系统层"，业务组件在 `src/components/` 包装它们。
- 设计令牌集中重建于 `src/styles/globals.css`（Tailwind v4 `@theme` + `.dark` 覆盖 + keyframes + 组件专属类）。
- 暗色：沿用 `class="dark"` 策略（与本项目一致，组件已验证兼容）。

### 10.3 设计令牌与全局 CSS

- **颜色**：`ink(1/2/3)`、`accent(+accent-ink/accent-tint)`、`orange`、`green`、`red(+red-tint/green-tint)`、`purple`（v1.5 新增，flowchart 条件卡）、`surface`、`canvas`、`page`、`field`、`line(+line-strong)`、`inset`、`hover(+hover-2)`、`white`；另补源码审计新增的 `--tooltip-bg/fg/muted`、`--grid-line`。
- **双层定义（v1.5 执行要点）**：裸 CSS 变量（`--ink` 等，供组件内联 style）+ `@theme inline` 映射（`--color-*`，供工具类）——暗色只需覆盖裸变量一层。
- **阴影**：`shadow-overlay/hairline/btn/card/raised`；**圆角**：`rounded-control/card/chip`；**字体**：Inter + JetBrains Mono。
- **keyframes**：`pixel-on`、`shimmer-text`、`pop-in`、`fade-in`、`fade-up`、`eq-bounce`（`spin` 为 Tailwind 内置）。
- **组件专属类**：`primitive-*`、`records-*`、`sidebar-*`、`insight-chart-*`、`source-avatar`、`animated-underline`、`filter-status-*`；自定义时长 `duration-400/250`。
- 完整 `@theme` 片段与 `.dark` 覆盖见 `前端设计系统落地方案.md` §3，落地时写入 `globals.css`。

## 11. 样式与主题

- Tailwind 4 **双令牌体系并存**：shadcn theme tokens（`--background` 系，仅供 shadcn/ui 基础组件）+ BUI 令牌（`--color-*`/`--shadow-*`/`--radius-*` 等 `@theme` 变量，**仅定义于 `src/styles/globals.css`**，供 `bui/` 组件）。两者命名空间不重叠、互不覆盖；禁止业务代码内重复定义或跨体系混用。暗色模式仍经 `class="dark"` 切换并持久化，两套令牌的 `.dark` 覆盖同置 `globals.css`
- 消息流虚拟化：单会话 >200 条启用 `virtua` 列表（防长会话卡顿）
- 无障碍：气泡 role=log、打字机文本提供"立即显示全部"按钮（skip）
