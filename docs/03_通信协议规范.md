# 03 通信协议规范

> **版本**: v1.0 | **日期**: 2026-08-23 | **适用对象**: 后端 / 前端
> **定位**: 定义线上**字节级**协议行为——REST 之外的一切：认证传输、SSE 帧格式、事件语义、超时重连、降级信号。端点与字段权威定义在 02；本文件与其同名同义，冲突以 02 为准。

---

## 1. 通信拓扑

```
┌────────┐  REST(JSON)   ┌──────────────────┐
│ 浏览器  │ ─────────────► │ FastAPI 业务面:8000│  请求-响应，一问一答
│        │               └──────────────────┘
│        │  SSE(text/event-stream) ┌──────────────────────┐
│        │ ──────────────────────► │ langgraph-server:8001 │  长连接事件流
└────────┘                         └──────────────────────┘
```

| 通道 | 编码 | 连接生命周期 |
|------|------|--------------|
| 业务面 REST | UTF-8 JSON | 短连接 |
| Agent 面 SSE | `text/event-stream` | 单 run 一个流，终态后服务端关闭 |

## 2. 认证协议

### 2.1 凭证获取与携带

- 兑换流程、JWT claims 结构见 02 §3.1 / §2.2。两服务共用同一 `JWT_SECRET`（HS256）
- 所有请求携带 `Authorization: Bearer <jwt>`；API Key 仅用于兑换（`X-API-Key`）

### 2.2 Token 过期处理时序

```
任意请求返回 401 AUTH_401_TOKEN_EXPIRED
   → 前端拦截器捕获(06 §5)
   → POST /auth/token 重兑换(限 1 次防循环)
   → 成功: 重放原请求; 失败: 清空 authStore 并跳转 /login
```

### 2.3 传输安全

- 生产环境两端口必须置于 TLS 反向代理之后（wss/https）；开发期允许明文 localhost

## 3. SSE 流式协议（J20）

### 3.1 请求

```
POST http://<agent>:8001/threads/{thread_id}/runs/stream
Authorization: Bearer <jwt>
Content-Type: application/json
Accept: text/event-stream
```

请求体结构见 02 §4（input + config.configurable）。响应头：

```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Degraded: no-graph          ← 可选，run 内已发生降级时出现（§5）
```

### 3.2 SSE 帧基础语法

```
: comment-line                 ← 冒号开头为注释帧, 用作心跳(§7)
event: <event-type>            ← 本帧事件类型
data: <single-line-json>       ← 载荷, JSON 序列化后单行
                               ← 空行 = 帧结束
```

### 3.3 事件类型总表

`streamMode: ["updates", "messages-tuple"]`（fast 档追加 `"messages"`，见 §4.3）：

| event 类型 | 方向 | 触发时机 | 载荷要点 |
|------------|------|----------|----------|
| `metadata` | S→C | run 启动 | `{run_id, attempt}` |
| `updates` | S→C | **每个图节点执行完成** | `{ "<node_name>": <state-delta> }` —— thought 步骤唯一来源 |
| `messages-tuple` | S→C | LLM 产出中间消息 | `[message_chunk, metadata]` —— standard/deep 档可仅用于进度展示 |
| `messages` | S→C | 仅 fast 档启用 | 逐 token 直推载荷（真流式直推，J8） |
| `values` | S→C | 图执行到 END | 完整终态 State（含 answer/citations/degraded…） |
| `end` | S→C | 流结束 | 空 data；随后服务端关闭连接 |
| `error` | S→C | run 异常终止 | `{error: {code, message}}`，错误码取自 02 §6 |

### 3.4 事件样例（standard 档一次完整问答）

```sse
event: metadata
data: {"run_id":"r_01J8...","attempt":1}

event: updates
data: {"load_memory":{"injected_working_turns":6,"episodic_hits":2,"dedup_removed":1}}

event: updates
data: {"query_understanding":{"intent":"factoid","rewritten_query":"清蒸鲈鱼的做法和蒸制时间","subqueries":[],"entities":[{"name":"鲈鱼","type":"食材"}],"latency_tier":"standard"}}

event: updates
data: {"planner":{"plan":[{"step_id":"step-0","tool":"dense","query":"清蒸鲈鱼 做法","depends_on":[],"status":"pending"},{"step_id":"step-1","tool":"fulltext","query":"清蒸鲈鱼","depends_on":[],"status":"pending"}]}}

event: updates
data: {"tool_router":{"new_evidence":9,"cache_hit":0,"retrieval_rounds":1}}

event: updates
data: {"reflector":null}          ← null 表示被 A2 短路跳过(未调用 LLM)

event: updates
data: {"generator":{"draft_chars":486,"citations":[1,2]}}

event: updates
data: {"self_correction":{"faithfulness_score":0.93,"passed":true}}

event: updates
data: {"write_back":{}}             ← 写侧尾节点(F4)：wm/episodic/rag_cache 副作用，无状态增量

event: values
data: {"answer":"**清蒸鲈鱼**的关键是控制火候与时间……[1][2]","citations":[{"marker":1,"result_ids":["r_88"],"quote":"水开后大火蒸 8 分钟"}],"degraded":false,"latency_tier":"standard","model":"deepseek-chat","token_usage":[{"model":"deepseek-chat","prompt_tokens":1841,"completion_tokens":512,"latency_ms":4200}]}

event: end
data:
```

### 3.5 载荷字段约定

| 字段 | 出现位置 | 说明 |
|------|----------|------|
| `degraded: bool` + `degraded_reasons?: string[]` | values 终态 | 取值同 02 §2.4 的 X-Degraded 枚举（no-graph/no-rerank/no-memory/llm-fallback/budget-exhausted） |
| `latency_tier` | values 终态 | auto 时回写实际档位 |
| `thought_steps` | 前端本地聚合 | 由 updates 序列在前端累积生成（node_name + 摘要），**服务端不发送该聚合字段** |

## 4. 三档位的流式行为差异（M1/J8）

| 档位 | 流内容 | 校验 | 前端渲染策略 |
|------|--------|------|--------------|
| fast（chitchat） | 追加 `"messages"` 模式，逐 token 直推 | 无校验 | 收到即渲染，无打字机模拟 |
| standard | updates + 终态 values（缓冲完整答案） | 无忠实度校验 | thought 实时折叠区 + 终态到达后 TypewriterText 回放 |
| deep | 同 standard | 自校正可能触发带约束重新生成（updates 会再次出现 `generator`） | 同 standard；重生成时提示"正在复核答案" |

> 铁律（M1）：standard/deep 在 values 到达前，前端**不得**把任何中间 LLM 文本当答案渲染——中间产物只进"思考过程"折叠面板。

## 5. 降级信号传递

| 通道 | 载体 | 前端消费点 |
|------|------|-----------|
| 业务面 REST | 响应头 `X-Degraded`（02 §2.4） | axios 拦截器写入全局 DegradedBanner 状态 |
| Agent 面 SSE | 响应头（启动即知） + values 终态 `degraded_reasons` | DegradedBanner + 消息气泡角标 |

多值逗号分隔：`X-Degraded: no-graph,no-rerank`。

## 6. 错误码通信相关子集

完整清单见 02 §6。SSE 场景专用规则：

- 流已建立后的错误以 `event: error` 帧交付（HTTP 层已 200），如 `CHAT_504_TIER_TIMEOUT`
- 流建立前失败走常规 HTTP 错误体（401/404/429 等）
- **待决项（缺口）**：流建立后 JWT 过期（deep 档读超时上限 55s 内可能发生）目前**未定义**处理路径——既无对应 `event: error` 也无前端重兑换。当前依赖 `client.runs.join` 续接机制，但 token 刷新策略需在 SDK/前端层明确；建议补 07 用例并在本规范定义行为（参考 02 §2.2 重兑换时序）。

## 7. 心跳 · 超时 · 断线重连

| 项 | 约定 |
|----|------|
| 服务端心跳 | 每 15s 发送一行注释帧 `: keep-alive`，防止代理层空闲断连 |
| 客户端读超时 | fast 10s / standard 30s / deep 55s（≥ M3 wall_clock_budget 上限 45s + 余量） |
| 断线重连 | langgraph-sdk 内建恢复：以同一 thread 重连后可用 `client.runs.join(threadId, runId)` 续接未完 run；前端无需自实现指数退避 |
| 幂等性 | run 创建支持 `multitask_strategy: "interrupt"`：同 thread 新 run 自动打断旧 run，避免并发写状态 |

## 8. precheck 短路交互时序（J22）

```
用户输入提交
   │
   ├─① POST /chat/precheck (业务面) ──hit──► 直接以缓存 answer 构造 AssistantMessage
   │                                          (标记 cache_score), 不发起 run, 结束
   │ miss
   ├─② client.threads.create()(若该会话无 thread)
   ├─③ runs.stream(...configurable.latency_tier=model 可覆盖 suggested_run)
   └─④ 按 §3.3 消费事件流
```

- ①与③之间 UI 显示"思考中"骨架屏；precheck 网络异常按 `{hit:false}` 处理，绝不阻塞主链路
- 命中条目由后端图内尾节点异步写入（前端无感知）

## 9. HITL 中断预留（E2/J20，当前默认关闭）

当图内 `interrupt()` 被激活（`agent.hitl.enabled=true` 且 deep 档命中高成本操作前）：

1. 流以 `event: updates` 携带 `{"__interrupt__": {...}}` 后暂停，run 状态变为 `interrupted`
2. 前端渲染确认对话框（如"即将执行外部 Web 检索，是否继续？"）
3. 恢复：`client.runs.resume(threadId, resumePayload)`，payload 形态 `{ "action": "approve" | "abort", "note?": string }`
4. 未来原生 WebSocket 通道升级时，本节事件语义保持不变，仅传输层替换
